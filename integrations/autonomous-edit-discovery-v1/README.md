# Automatic new edit -> failed-case evidence -> v7 patch workflow

The first adapter generates NEW registered551 trajectory edits, not another run of the old canonical cut-in. Baseline means the inherited accepted controller. Each legal candidate edit receives fresh original/edited runs of that controller, an independent repeat, and fresh runs of the highest-scoring research alternative on the identical world. Scene/seed/model/actor contracts must match. Completed reproducible performance gaps with an executed feasible alternative may be admitted; infrastructure errors and illegal edits cannot become failures. Hard early-termination baselines currently remain unadmitted because v7's paired convergence/acceptance contract requires complete baselines; they are not silently converted to healthy episodes.

After admission, the host writes failure_reason.json, edit_instruction.json, task.json, admission.json and selected_task.json. The same worker immediately calls the real v7 Engine with a concrete NewEditAdapter. API settings come from the launch environment. The model must causally analyze, generate an exact permitted patch and a parent-fail/candidate-pass test; all existing controller CPU/native/replay checks remain. Actual candidate evaluation runs the new original/edit pair plus the old cut-in again, on fresh histories. Old best score and stable lateral/progress/stop gates remain protected. Missing other-scene adapters remain missing, never generalized by relabeling551 assets.

Entry: integrations/autonomous-patch-agent-v7/new_tasks.sh

First start must explicitly specify the supplemental wall/GPU allocation, because the old campaign exhausted its wall budget. These allocations are persisted; restart never resets them. All old API/token/round/GPU usage carries into the child v7 campaign. API tokens remain under the original total2million cap. The old campaign, candidate pool and acceptance records are unchanged. A source snapshot and measured new frontier are separate, so old-edit scores never become new-edit scores.

Example after CPU preparation/testing:

```
bash integrations/autonomous-patch-agent-v7/new_tasks.sh start --extra-wall-seconds 14400 --extra-gpu-attempts 16
bash integrations/autonomous-patch-agent-v7/new_tasks.sh brief
```

If no generated edit satisfies admission, the service writes waiting_new_edit_family. If the API is missing, v7 waits_api after finding a task. Complete GPU validation of this new discovery-to-patch chain is required before calling it experimentally demonstrated. The first version supports this new551edit family;172/552/621 still require matching runtime/map/evaluator admission despite cached semantic assets.
