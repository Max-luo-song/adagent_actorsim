# v6 边缘问题诊断与受约束修复

v5 修复了图像索引和留出帧光照条件，重新生成的数据训练后，新视角 L1 从 0.0288101 降到 0.0272663（改善 5.36%），但边缘误差从 0.01244035 增到 0.01244722（退化 0.055%）。因此上一轮没有通过清晰度门槛。

已确认的两个限制：

- 抽查 frame 9/29 的三个相机，现有边缘项对 RGB 的加权梯度范数平均只有 L1 项的 12.58%、SSIM 项的 6.92%。这是保存图像上的梯度诊断，尚不能替代高斯参数梯度证据。
- v5 实际只更新 Background DC、Road DC/SH 三组颜色参数。尺度、透明度全部冻结，无法通过改变高斯覆盖范围修复重叠产生的模糊。是否构成当前主要瓶颈，需要实际渲染梯度和对照训练确认。

独立 v6 不修改 v5 或运行时框架。复用 v5 已校正的 174 个监督样本，两个实验都从同一个 v5 候选权重开始，训练 6 轮，原视角和新视角 1:1 交替：

| 实验 | 颜色损失 | 可更新参数 |
| --- | --- | --- |
| edge_color | L1 0.8、DSSIM 0.2、edge 0.8 | 原有三组颜色参数 |
| footprint | 相同颜色损失，附加深度/透明度保持项和参数约束 | 同上，加有支持的 Background 尺度和透明度 |

footprint 只允许原视角**训练集至少两个不同时间戳**可见的背景高斯调整；同帧三个相机不算三个时间戳。可见性通过中心投影与 v5 渲染深度一致性近似，不作为真实几何标注。尺度限制在 v5 的 85%–105%，透明度 logit 改变量最多 0.2，未获支持的点完全恢复原值。所有中心、旋转、道路几何、动态对象、光照和标定保持原值。

先保存 v5 静态区域的预期相机 Z 深度和透明度，然后对实际高斯参数做梯度检查。仅在支持点数量和非零有限梯度通过后才运行 footprint。深度来自自渲染，属于保真代理，不能证明真实几何正确。footprint 改变渲染覆盖范围，不能宣称全部几何不变。

运行（在 GPU 终端，无需设置 P26）：

```bash
bash ${HUGSIM_ROOT}/integrations/novel-view-distillation/detail_v6/run.sh all
```

输出目录打印为 `Detail v6 output:`，位于 `phase26/novel_distillation_v6/runs/<UTC>/`。该命令按顺序执行缓存、梯度诊断、两组训练及各自验证，阶段间释放进程；不会重新运行 DiFix。

主要文件：

- `probe.json`：真实渲染参数梯度、支持点数量、实际获准实验组。
- `<profile>/evaluation/report.json`：清晰度、原视角回退、静态深度/透明度变化检查。
- `<profile>/evaluation/before_teacher_after.mp4`：上排 v5 同一新轨迹，中排 DiFix 伪 GT，下排 v6 同一轨迹。
- `comparison.json`：两组指标及是否存在通过门槛的候选。未通过则推荐值为 null，不自动放宽门槛。

门槛包含：边缘误差比 v5 至少改善 2%；保留相对蒸馏前的 5% L1 改善且相对 v5 回退不超过 1%；原视角 PSNR 回退不超过 0.2 dB；原视角平均相对深度变化 ≤0.5%、每图 p95 的均值 ≤2%；新视角对应 ≤1%/3%；平均透明度变化 ≤0.01、新空洞比例 ≤0.1%。通过也只进入人工复核，仍需闭环重新验证，不自动替换仿真权重。

可分阶段执行：`run.sh cache OUTPUT`、`run.sh probe OUTPUT`、`run.sh train OUTPUT edge_color`、`run.sh evaluate OUTPUT edge_color`、同样执行 footprint 后 `run.sh compare OUTPUT`。阶段产物存在时拒绝覆盖；失败时检查对应日志，不要删除已完成的训练权重。

CPU 测试覆盖支持点筛选、不同时间戳计数、更新范围/边界、深度约束，以及可微模拟渲染器下的两组缓存→梯度→训练→保存→重载→评估完整流程。真实 CUDA 效果须以 GPU 运行产物为准。
