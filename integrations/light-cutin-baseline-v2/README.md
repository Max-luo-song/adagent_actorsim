# 原场景551轻量基线 A-v2

本版本解决旧A初始化与慢速参考不相容、起点缺少地面评测支持的问题。复用原目录的固定iLQR、原生Motion、UniAD模型及验收规则；旧A的结果与准入拒绝记录全部保留。

这里修正的是实验初始化条件，**不宣称已解决UniAD低速输出的模型根因**。已核验旧A的16m/s真实输入到达模型CAN bus，原始规划与导出规划相同，模型输出本身为累积XY、0.5s采样，执行为0.1s。模型域适配及全部感知校准仍不能凭这些检查认证。

## 固定条件

- 初速4m/s，基于旧A已经观测到的约4.13m/s首段参考；不读取新一轮未来预测来设定自车状态。
- 从原场景源第10帧/1.0s对应的原始位姿建立新episode。只在初始化时设定一次anchor，此后每步由Motion.advance推进并重新渲染/运行UniAD。
- 原生已知地面在该初始车体位置DAC=1，无原生前景包围盒重叠。这只证明该处初始覆盖有效，不保证未来执行评分。
- 渲染、碰撞及评分的参与者时钟均为源帧10加本地步数；模型时间从0开始。源时钟和模型本地时钟分别记录，不把车辆固定在第10帧。
- 与旧版相同：70控制步/7s观察、1800s驾驶墙钟上限，跟踪误差1m与执行DAC门槛等准入逻辑不变。没有绕过拒绝记录。
- 原始车辆、道路及天气不变；没有候选补丁，不执行重型MPC或避障搜索。

新旧A起点和初速不同，不能把两者分数差当作控制器或补丁效果。v2只能作为后续配对实验的新共同基线。

## 执行

准备目录已创建，无需重复prepare：

```bash
D=${HUGSIM_ROOT}/integrations/light-cutin-baseline-v2
bash "$D/run.sh" check
bash "$D/run.sh" baseline
```

实际输出：`outputs/gpu_test_service/jobs/unified-open-closed-172-20261022-v4/chain_repair/phase26/light_baseline551_v2/`。

GPU不可用、实际进程冲突、锁占用或STOP存在时不启动；不停止已有任务。检查通过的已有A可复用，失败记录不覆盖，也不自动重试。

驾驶完成后独立读取结果和生成回放：

```bash
bash "$D/run.sh" inspect
bash "$D/run.sh" render
```

回放上下两行均为同一个A，不是A/B。原生raw_uniad与adopted_plan评价规划，executed_path评价实际记录的未来执行，不能混淆；原生DAC仍为重建点云代理，独立HD道路边界未知。

本入口**拒绝B和补丁**。旧切入脚本按16m/s自车设计，不能移植到4m/s后直接使用。A-v2通过后，必须重新设计并预注册目标原车的轨迹、实际相对间距和共同历史分叉，才开放B。

CPU验证包含：真实Motion的执行反馈、新旧时钟在每步渲染/碰撞/模型输入中的一致性、原生评分参与者帧偏移及实际执行轨迹导出、B/补丁在运行前拒绝。神经推理在单元检查中为明确的模拟服务，不能当GPU驾驶证据。
