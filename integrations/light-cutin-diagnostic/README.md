## 场景与唯一干预

实际源为waymo551、199帧、0.1s仿真步长，checkpoint位于 `waymo_551/20260419_lidar+cam0_1_2adstudiov_pbr_3view/checkpoint_final.pth`。目标为 `native:RigidNodes:3`，原始实例5，标注ID `o24FGKGBO7aPlRVYkDyU7A`。已核对初始中心、尺寸与原标注一致。

A保持所有车辆原始行为。B只覆盖这辆原车的运动轨迹，不插车、不改其他参与者、道路或天气。准确类型为**脚本化车辆轨迹干预**。

固定自车初速16m/s，两臂相同；源录制初速约20.09m/s，本实验明确采用较低初速，使原左后车能在进入自车道前向前超越。目标初始位置约forward=-5.54m、left=4.31m。1.2s开始向source负y方向切入，持续2.8s；3.8s开始平滑减速，持续3.5s，名义终速10m/s。轨迹由原有效渲染轨迹连续重定时，不瞬移。

冻结轨迹审计：最大速度22.27m/s、加速度6.96m/s²、路径偏航角速度0.204rad/s、车体偏航角速度0.199rad/s；预定上限35m/s、8m/s²、0.8rad/s。在7s观测＋2.5s评分支持内，与其他原生车辆无穿越，最小多边形距离约16.13m。实际切入是否进入**执行中的**自车前方，必须由GPU闭环日志验证，不能用名义初速假定。

编辑器、渲染器和碰撞代理共享原始位姿张量，目标点数、尺寸、可见性及15辆RigidNodes数量保持不变。复用原SH旋转上下文。留出帧按551实际stride=10的渲染插值处理，共同前缀不启用新的上下文覆盖；CPU已验证其他车辆与前缀值不变。实际GPU像素同步仍待验。

## 运行顺序

本次准备目录已经创建，**不需要再次prepare**：

```bash
D=${HUGSIM_ROOT}/integrations/light-cutin-diagnostic
R=${HUGSIM_ROOT}/outputs/gpu_test_service/jobs/unified-open-closed-172-20261022-v4/chain_repair/phase26/light_cutin551_v1
bash "$D/run.sh" check "$R"
```

在GPU终端、现有任务无冲突时先执行原始A：

```bash
bash "$D/run.sh" baseline "$R"
```

A运行70个控制/7s，同时完成必要的初始短窗口与完整原始对照，避免另起重复探针。若A异常或不足窗口，阻止B，先查 `A/error.log`、`A/summary.json` 和原生评分；不把基线问题包装成切入问题。

A通过后：

```bash
bash "$D/run.sh" pair "$R"
```

此阶段校验并复用A，只运行B。持有GPU服务锁并检查实际GPU进程；锁忙、STOP存在或CUDA不可用均拒绝启动，不清理他人任务。每臂7s是仿真观察上限；1800s为含启动的驾驶墙钟资源上限；单次推理300s、模型启动1200s、原生评分900s。观察上限结束不是绕行成功证据。

共同状态通过**完整前缀重推理**重建：B从真实初始状态逐步渲染并运行UniAD，核对共同前缀图像、全部导出神经输出、动作及实际位姿，复用已经执行过的共同历史动作；不读取预存未来轨迹，不在分叉处重置模型。旧重型MPC快照及旧不完整张量快照均不复用。像素要求完全相同，神经输出容差1e-4、动作1e-5、位姿1e-9；失败即停止，不放宽标准。

已有有效结果可独立分析/呈现，不重跑驾驶：

```bash
bash "$D/run.sh" diagnose "$R"
bash "$D/run.sh" render "$R"
```

已完成且哈希有效的驾驶、评分及视频会复用。失败/不兼容运行不会覆盖，需先定位；不自动重试驾驶错误。

## 诊断记录与评分

每步保存实际Motion状态、动作、当前三相机、目标真值位姿/速度/相对位置（仅事后诊断）、UniAD检测/占据/原始规划、原始运动头张量和同调用查询关联、采用参考、选择来源及拒绝原因、跟踪误差和结束原因。新增运动头包装只复制输出并原样返回原对象，不修改网络计算或权重。

`target_detection_association_reference_only.json`将当前目标真值转换到声明的虚拟LiDAR坐标，记录最近候选/保留检测/运动查询。它不是在线目标选择，也不宣称最近中心等于可靠身份关联。

`comparison_A_B.json`记录首个像素、检测、运动预测、原始规划、采用参考、控制及执行状态差异；相机差异必须在自车状态分化前出现才可确认干预观测证据。后续同一时刻的图像同时受目标干预和自车视角改变影响，单独标注，不能只凭总分归因。

停驶≥1s作为事件，低速≤0.2m/s且位移≤0.3m持续≥3s作为停滞候选；仅当采用参考在最后≥1s仍要求≥2m/s时记为跟踪异常停滞。正常减速让行和观察结束时尚未恢复不会自动算失败；恢复定义为停后速度>1m/s持续≥1s。

原生评分复用现有native evaluator、export helper和聚合算法，分别输出：

- `raw_uniad`：原始规划评分。
- `adopted_plan`：外部处理后的参考规划评分。
- `executed_path`：已经执行的实际未来0.5s节点，只有完整记录了2.5s执行窗口的起点才评分。不填充未发生的执行轨迹。

三条流在有执行支持时采用相同关键帧，评分项为NC、DAC、TTC、comfort、PDMS、RC、HD-score。实际碰撞、路线偏离、进度、停驶/恢复和运行耗时另报，不能把前两种规划评分解释成执行效果。

处理后的551数据没有独立HD道路边界；保留原生路线偏离10m终止和实际执行的DAC代理，真实HD越界字段为null。语义未知点使用既有原生评分上下界，不伪造单值认证。背景环境碰撞按原生opacity过滤，评分保持已有评测点云密度，这两个输入范围明确分开。
