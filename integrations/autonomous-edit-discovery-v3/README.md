# LLM scenario design -> v15 failure discovery -> v8 patches

`integrations/autonomous-patch-agent-v8/llm_tasks.sh` adds model-authored editing before real failure discovery. Current admitted editing capability is551's registered original-car multi-stage action program. The LLM chooses2..6 ordered phases: lane change, decelerate, accelerate, cruise and stopped hold; phases may combine speed changes with lane intents. Supported lanes are the original lane and the ego lane, including return maneuvers. Single displacement perturbations and no-op sequences are rejected. The model receives verified scene/map/participant metadata, supported capability ranges and measured feedback; other scenes are explicitly unavailable until their runtime/scorer adapters are admitted. Arbitrary scene IDs, vehicles, scripts, commands, filesystem paths, controller changes and score edits are rejected.

The model proposes1..4 genuinely new configurations in strict JSON. Hypotheses are not failure evidence. Host code supplies stable case IDs and compiles the scalar parameters, checks dynamics, prefix/actor identity, other-participant clearance and offline feasible-path evidence. Actual fresh v15 trials and independent repeats decide whether a problem exists. Only qualified evidence automatically enters v8 causal diagnosis, minimal patch construction, CPU/native/replay checks and new closed-loop regression. The global default remains v15 until the normal confirmation process; no scene-specific controller branch or held-out tuning is authorized.

Model proposals, request/progress/response files, CPU rejections, GPU findings, failure_reason.json and edit_instruction.json are automatic durable files. Model fixture output cannot become a live edit. A fully received response is recovered without another API call. Interrupted unknown calls retain conservative reservations. Scenario design and patch analysis share the original API/token cap; previous tokens, rounds, GPU attempts and wall start are carried, never reset.

The new worker waits for the current discoveryv2 worker to release its lock, preserves its paused patch checkpoint and cumulative usage, and prioritizes the new user-requested multi-stage scene discovery without first running the old offset task. Active v2 source and episodes remain unchanged. Then v3 snapshots latest usage and reserves the previous lock to prevent accidental parallel spending. First-launch optional --add-wall-seconds and --add-gpu-attempts are explicit additive allocations, applied once. Resume without flags reuses the same allocation. New API keys stay in the coordinator environment; native jobs strip them.

```
bash integrations/autonomous-patch-agent-v8/llm_tasks.sh resume --add-wall-seconds 14400 --add-gpu-attempts 12
watch -n 5 bash integrations/autonomous-patch-agent-v8/llm_tasks.sh brief
```

No fixed manual edit grid is used as fallback when the model/API is unavailable. Missing API waits; invalid edits are rejected before GPU; exhausted budgets stop. Test fixtures validate software behavior only and are not evidence of a real model-created failure or a successful patch.


Action payload schema is `scene_action_proposals_v2`; program is `native551_car3_action_sequence`. Each phase declares `action`, `duration_s`, `target_speed_ratio` and `lane`. Ratios retime the observed source vehicle trajectory; they are not absolute speeds. Host quintic transitions integrate the speed clock continuously, preserve the original prefix exactly, and audit actual speed/acceleration/yaw, all other actors and source support. Stop-hold requires actual zero speed; restart requires a later acceleration phase. Invalid or unavoidable designs never become a claimed controller failure. Examples and actual CPU audits are in `checks/action_examples/`; examples are software checks, not a fallback edit grid or model/GPU evidence.
