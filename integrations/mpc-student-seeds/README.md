# 学生初值 → 原 MPC 优化（CPU 配对试验）

复用离线 MPC 蒸馏的 `20261109T084609Z/student/policy.pt`，不重新训练，不让网络直接控制车辆。该模块是独立实验，不修改 phase45 或当前闭环默认文件。

## 搜索流程

1. 原 warm/道路起点、coast 和左右 escape 仍按原顺序、原 220 次迭代预算执行。
2. 若原有收敛一致性门槛已满足，直接结束，不计算学生特征或调用网络。
3. 进入扩展搜索时，用当前道路、占据、历史包络及当前状态构造原有描述子，计算三个已训练模式。投影至原车辆控制限幅，排除与原起点重复及非有限的预测。按当前初值约束余量/目标排序，最多额外试一个初值。
4. 学生初值仍由原 SLSQP 在完整目标和约束下求解，预算保持 220。必须实际收敛、未跳过优化、未退回未优化初值，并满足原收敛一致性使用的道路/进度/速度/舒适性条件，才可参与最终方案选择。
5. 学生失败则继续原扩展起点；只有原有不同起点间的 1% 目标一致性门槛通过，才允许结束搜索。

训练分布外状态会记录，但这里允许其提供优化初值；它不能直接变成控制。当前问题求解和完整约束检查仍然必需。初值本身允许不可行，由原求解器尝试修复；不可行预测不等于可执行轨迹。

## 隔离与校验

从配置完成的原 controller 复制 globals，提取并编译独立 optimize 函数；仅两个可逆文本修改：扩展候选生成调用、额外学生行的求解后准入。源模块 optimize、EvidenceGuard 绑定及源文件保持原样。`__file__` 保留源路径，以保留既有相对配置读取语义。

每个学生实验记录源 controller 哈希、原函数/适配函数哈希、完整适配函数文本。目标函数、道路惩罚、动力学、几何、制动后备、控制限幅和原起点迭代预算没有修改。

## 配对验证

```bash
bash ${HUGSIM_ROOT}/integrations/mpc-student-seeds/run.sh all
```

三个预先登记的固定输入：测试场景步骤0、8、23。每个输入的 baseline 和 student 依次在独立进程中重新求解，步骤8反转执行顺序；使用相同观测、warm 和完整预算。它们已在上一轮用于测试，因此本轮属于开发对照，不能算新的泛化测试。

输出为 `phase45/policy_distill_v1/student_seed_runs/<UTC>/`。计时包含当前问题构造、特征、网络、初值排序与 MPC，独立重建验证在计时之后。结果由原 controller 的问题接口重新核对约束、状态和目标。`comparison.json` 展示每帧目标、求解起点数量、耗时与退化；仅在质量检查全部通过、总耗时降低时标记性能准入。没有闭环实测或自动提升默认版本。

6项测试覆盖不展开时零网络调用、完整保留原起点、原判停门槛、非收敛/未优化初值拒绝、源 controller 不被修改，以及真实问题和网络的初值生成。
