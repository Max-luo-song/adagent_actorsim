# 跨场景闭环与原生评分适配

新增宿主接口，不改v13/v15/v17控制器、iLQR、安全证书或HUGSIM评分公式。运行前仍必须通过逐场景真实资产准入。它不是新的控制补丁，不能据接口测试宣称泛化有效。

- `maps`：融合每个场景自己的198帧原始标定、相机曝光位姿、完整19类语义、置信度、地面点云。独立帧投票，遮挡与冲突记未知；不填孔、不取凸包、不沿记录轨迹造固定路宽。原始数据没有HD地图，不冒充白实线或物理边界真值。
- `check`：检查地图/源数据哈希、初始完整车身及原有安全余量；分别启动v13/v15/v17的CPU导入检查。明确报告未准入项和已有共享预算。
- `prepare`：每个场景/版本独立目录、自己的源清单/演员/导航/起点/评分资产和相同声明时长。所有比较臂独立感知历史，不复用551动作或演员。默认100控制步，原始frame10开始；不为通过结果而调整起点、时长、车身或门槛。
- `execute`/`full`：仅在准入后才允许实际GPU运行。共用GPU锁、STOP和原campaign预算，计数不清零。现有累计墙钟预算已耗尽时必须先明确追加预算；不能伪造启动。

原运行器中的scene551、固定直行指令、15辆车校验与551演员对照路径，改为白名单宿主绑定。策略process/admit/Motion.advance调用AST保留。原生评分的BUNDLE/SCENE_BUNDLE只绑定本场景资产，保留相同原生算法和未知语义上下界；没有确定的executed_path分数不能正式验收。

真实验证失败之后的整池退役/公开原因/转训练/新池验证仍沿用autonomous-patch-agent-v8/VALIDATION_LIFECYCLE.md。本模块只提供运行组件，不绕过收敛、回归、验证集隔离和全局晋升证明。

## 一键补齐替补候选场景

原定三个起点未通过传感器道路覆盖检查，不视作补丁失败，也没有消耗或公开任何真实验证分数。按资产覆盖条件、在任何新控制器评分前，额外登记31与233；各199帧源几何及原始记录身份校验已经完成，语义/点云语义等待GPU准备。不会静默搬动原场景起点或缩短闭环时长。

GPU终端执行：

```bash
D=${HUGSIM_ROOT}/integrations/cross-scene-native-v1
bash "$D/run.sh" bootstrap --seconds 14400
```

这次明确提供从调用时起4小时的追加墙钟窗口：原始开始时间、已消耗tokens/GPU次数不清零，旧配置与预算事件会归档。只有新语义GPU任务才计一次GPU派发，已有有效缓存直接核验；GPU锁与STOP继续生效。中断的语义按已核验图像恢复，未完成的数据/原始记录/点云目录归档后重新计算，绝不当完成缓存。

bootstrap仅补齐资产和自动检查准入，**不等于已通过泛化**。所有资产合格的场景在任何控制器分数产生前冻结到validation_pool.json；不足两个时继续等待，不造地图或偷换验收门槛。现有未准入起点保留诊断及拒绝理由。

`cpu`生成绑定当前代码的离线准入记录；`full`要求该记录及冻结场景池有效，且共享预算足够，才会运行各参考版本的独立原生闭环。完成矩阵仍须进入v8正式泛化证明/退役和发布流程，本模块不直接改global_patch.json。

## 更新：镜头投影有效域修复

当前地图使用maps_principal_branch_v2，诊断使用diagnostics_principal_branch_v2。原maps与diagnostics下所有旧文件保留为历史，不应再用旧投影负票推断物理非道路。见phase26/cross_scene_native_v1/projection_repair_v2/README.md和修复证明。

发现的全局实现缺陷是畸变多项式的折返分支也可被映射到图像内。当前统一检查与光轴相连的物理主分支、正径向导数和正定投影Jacobian；没有场景/方向例外。地图与点云都使用这一检查。2D语义图像无需重推理；3D点云语义必须使用独立v2输出，不复用旧标签，新原生评分也禁止回退。

修正后的全帧有效起点扫描仍无法使172/552/621保留100步窗口。不能据此缩短时长或填补未知路面。31/233仍待GPU资产准备；bootstrap保持原计数及显式追加时限语义，但会生成正确版本点云及地图。基础设施修复不算控制补丁，也不计入收敛或分数收益。
